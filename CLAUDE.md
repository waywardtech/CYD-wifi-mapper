# CYD Wi-Fi Mapper — notes for Claude Code

Firmware + setup web app for a Wi-Fi survey tool on the ESP32-2432S028R (CYD). Read `README.md`
first for what it does; `docs/DATA_FORMAT.md` for the files it writes.

## Commands

- `pio test -e native` — unit tests for `lib/core` (fast; run after any core change)
- `sim/run.sh` — renders every UI screen to `sim/out/*.png`; **look at the PNGs** after UI changes
- `python test/web/test_web.py` — web app end to end in headless Chrome (needs `pip install playwright`)
- `python test/web/test_autotrace.py` — plan auto-tracing on generated sheets; **look at**
  `sim/out/autotrace_*.png` after touching `detectPlan`
- `pio run -e cyd -e cyd2usb` — firmware must build for both variants
- `python tools/build_artifact.py && python test/web/test_emulator.py` — browser build of the
  device app (`dist/artifact.html`, published as the "CYD Wi-Fi Mapper" Claude artifact);
  screenshots in `sim/out/emu_*.png`. Anything added to `wm::Platform` or `wm::Canvas` needs a
  matching import in `wasm/wasm_main.cpp` and `web/emulator.html`.
- `python tools/readme_images.py` — regenerates `docs/images/` for the README from the simulator,
  the browser build and generated plan sheets (run `sim/run.sh` and `tools/build_artifact.py`
  first). Rerun it after UI changes so the README stays truthful.
- `python tools/mock_device.py` — serve the web app locally against a fake SD card

## Rules of the road

- `lib/core` must stay free of Arduino headers. Hardware goes through `wm::Platform` and
  `wm::Canvas` (see `wm_core.h`). `src/main.cpp` is glue only; behaviour belongs in core where
  it can be tested.
- RAM is the constraint (no PSRAM, ~520 KB total, Wi-Fi takes a lot). The screen is drawn in
  four 320x60 bands through one 16-bit sprite; `App::draw` is called once per band and must
  cull by `Canvas::bandY0/bandY1`. Do not allocate a full-screen 16-bit sprite.
- `samples.jsonl` is append-only (undo is a tombstone line). Keep it that way.
- The web app is one file with no external resources: it is served from a hotspot with no
  internet. Pure helpers are exposed on `globalThis.WM` for the browser test.
- The same `web/index.html` is published as a Claude artifact and runs standalone (no device
  API). So: no `alert`/`confirm`/`prompt` (use `notify`/`sure`/`askText`), storage only through
  `store`, files only through `saveFile` with a Copy fallback. `test_web.py` fails if a native
  dialog fires.
- `src/web_assets.h` is generated by `tools/embed_web.py`; never edit or commit it.
- Blocking work (Wi-Fi scans) is requested via `App::pendingScan` and runs in `tick()` only
  after the "Scanning" overlay has been drawn.

## Automatic plan tracing (`detectPlan` in `web/index.html`)

Runs in the browser on a greyscale copy scaled to ~1800 px. Walls = thick strokes (stroke width
from run lengths); text-sized blobs dropped; openings sealed by bridging collinear wall runs
(short gaps = doors, any gap that thin/faint ink spans = windows); outside flooded from the sheet
edge; each remaining region is a plan. Outline = traced boundary, simplified and squared up.
Interior walls = long horizontal/vertical strips of wall pixels, minus those hugging the outline.
Fallbacks in order: solid walls, double-line walls (strip between long parallel lines is filled),
single-line sketch. Known gaps: angled walls, garage doors drawn dashed, plans whose exterior
openings have no line across them wider than 10 wall-thicknesses, and anything hand-drawn or
photographed at an angle. When a real plan fails, add it (or a redrawn equivalent) to
`make_plans.py` as a new case before changing thresholds.

## Not yet verified on hardware

The bit-banged XPT2046 read (`tRead`, shift of 3), default touch ranges, 3-tap calibration,
SD on VSPI alongside the display on HSPI, scan duration, and free heap with the hotspot up.
Treat reports from a real device as ground truth over anything in the simulator.
